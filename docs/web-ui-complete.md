# Web UI — Complete Control Plane\n\nThe Web UI is a local-first control plane for LiteRT Agent. It shares the same runtime, SQLite state, security policy, approval manager, event bus and LiteRT-LM-only model provider used by CLI/TUI.\n\n## Start\n\n    litert-agent web\n    # http://127.0.0.1:8765\n\n## Information architecture\n\n### Operate\n- Dashboard — runtime health, model readiness, resources, queue and live events.\n- Chat — operational chat; hidden chain-of-thought is never exposed.\n- Agent — identity, autonomy, provider, queue and health.\n- Tasks — task creation and task state.\n- Plans — plan/verification overview linked to persisted tasks.\n- Live Execution — WebSocket execution stream.\n\n### Build\n- Memory — searchable memory inventory.\n- Skills — skill registry and lifecycle visibility.\n- Tools — tool registry and permission levels.\n- Workers — logical worker pool and queue state.\n- Browser — browser capability/policy surface.\n- Research — missions, evidence, provenance, credibility and LiteRT-LM synthesis.\n- Goals — persistent goals, dependencies/priority state and curiosity queue.\n\n### Control\n- Scheduler — persisted jobs and manual execution.\n- Approvals — allow-once, allow-session and deny decisions.\n- Security — policy visibility and security boundary.\n- Checkpoints — recovery snapshots and restore.\n- Audit Log — event/audit history.\n- Logs — runtime event log viewer.\n\n### System\n- System — OS, Python, CPU/RAM/disk and capabilities.\n- Model — LiteRT-LM CLI capability and health.\n- Diagnostics — bounded self-test.\n- Settings — complete configuration visibility.\n- Self-X — bounded self-awareness, research, goals, maintenance proposals and safety controls.\n\n## UI rules\n1. Dark-first, responsive, glass/panel visual language.\n2. Every page has persistent navigation and runtime connection status.\n3. All user-visible data is HTML-escaped.\n4. Dangerous operations remain behind the existing policy/approval pipeline.\n5. The browser never becomes an unrestricted terminal.\n6. Internet content is untrusted evidence and never executable instructions.\n7. LiteRT-LM CLI is the only inference backend; there is no silent provider fallback.\n8. WebSocket events update live surfaces without exposing hidden reasoning.\n9. Mobile navigation becomes a drawer; wide tables scroll horizontally.\n10. The UI is an operator console, not a replacement for the agent security model.\n\n## Shared components\nMetric cards, status badges, tables, cards, forms, action buttons, notices, approval cards, event streams, log viewers, chat bubbles, settings panels, skeleton/loading states, error states and toast notifications.\n\n## API surface\nThe existing API remains the source of truth for runtime data. The Web UI consumes status, health, capabilities, tasks, memory, skills, tools, approvals, scheduler, workers, checkpoints, logs, system, settings and Self-X research/goal endpoints. /ws/events supplies live events.\n\n## Security boundary\nThe UI can request actions, but the backend remains authoritative. Tool execution must pass:\nModel → Parser → Validator → Policy → Permission → Approval → Tool\n\nSelf-X cannot automatically change model provider identity, security policy or model weights.
